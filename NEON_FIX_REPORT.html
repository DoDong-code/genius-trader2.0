Neon PostgreSQL statement_timeout 兼容性修复

文件：server/database/dbAsync.js · 状态：已提交（工作区干净）· 仅移位置、不删保护

① 根因

生产同时使用 Render + Neon。Neon 的 pooled connection 不接受把 statement_timeout 作为 PostgreSQL 启动（startup）参数传入：

# Render / Neon 启动报错
unsupported startup parameter in options: statement_timeout
# 导致 Cloud schema initialization failed → DB 进入 degraded mode

原实现把 statement_timeout 放进了 new Pool({ options: '-c statement_timeout=...' }) 的建连启动参数，正是 Neon 拒绝的对象。

② 修复方案（before / after）

移除启动参数（不再触发 Neon 拒绝）：

// 修改前
new Pool({
  // ...
  idleTimeoutMillis: 60000,
  options: `-c statement_timeout=${STATEMENT_TIMEOUT_MS}`   <-- 删除
});

// 修改后
new Pool({
  // ...
  idleTimeoutMillis: 60000
  // 不再有 options 启动参数
});

改为建连后按会话设置（保护保留）：

pool.on('connect', (client) => {
  client.query(`SET statement_timeout = ${STATEMENT_TIMEOUT_MS}`).catch((e) => {
    console.error('[dbAsync] 设置 statement_timeout 失败（非致命）:', e && e.message);
  });
});

事务路径用 SET LOCAL 兜底（Neon 事务池模式会话级超时不跨事务保留）：

await client.query('BEGIN');
await client.query(`SET LOCAL statement_timeout = ${STATEMENT_TIMEOUT_MS}`);

超时默认值仍为 15000ms；事务看门狗（PG_TRANSACTION_TIMEOUT_MS=20000，504 ROLLBACK）与 acquire timeout（503 快速失败）均原样保留。
