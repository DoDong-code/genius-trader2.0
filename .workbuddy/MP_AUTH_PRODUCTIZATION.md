## 一、现状盘点（代码事实）

### 1. 首次账户初始化（app.js `loadState` 133-164）

- 读 `genius-trader-portfolio-v2`，有 accounts → 恢复；无 → 生成默认：
  ```
  主账户 + 国泰半导体设备ETF联接C(019633) 10000元（holdingProfit=0）
  ```
- **这是 demo mock 数据**：019633 是「示例基金」，金额 10000 是假的。

### 2. 登录流程（login.js + app.js `login` 87-99）

- 入口：设置页账号栏「登录 / 注册」→ `pages/login`
- `app.login()`：`POST /api/auth/login` → 存 token → `GET /api/account/state` 恢复云端 → 返回
- 成功 toast + 返回上一页。

### 3. 注册流程（register.js）

- 入口：login 页「没有账号？去注册」→ `pages/register`
- 邮箱+密码+确认密码 → `POST /api/auth/register` → 复用 token → 设 auth → 返回
- **注册后不拉云端**（新用户云端空，合理）；但本地默认 mock「主账户」仍在，且**不自动同步**到新 user_id。

### 4. 账号中心（profile.js + setting 账号栏）

- profile 页：显示 email（登录后）、立即同步、恢复本地、退出登录、备份列表
- setting 账号栏：显示 email + `#user_id`
- 游客模式：显示「未登录，数据仅保存在本机」

## 三、建议的产品流程（目标态）

### 1. 首次初始化（改 P0-1）

```
全新用户首次打开
→ 空账户「主账户」（无 mock 基金）
→ 持仓页显示空状态：「还没有基金，点 + 添加」
→ 引导添加第一只基金（复用现有添加基金弹窗）
```

> 关键决策：是否去掉默认 019633 mock？这是你早期「默认一个主账户一个基金」需求的遗留。产品化后建议改为「空主账户 + 引导」，避免假持仓误导。

### 2. 注册成功（改 P0-2）

```
注册成功
→ 进入「空账户」状态
→ 顶部引导：「已创建账号，现在添加你的第一只基金吧」
```

### 3. 登录成功

```
登录成功
→ 云端有数据：恢复云端账户，toast「已恢复 N 个账户」
→ 云端无数据：进入空账户，引导添加
```

### 4. 游客→正式用户（改 P1-1）

```
游客模式登录/注册时，弹窗提示：
「当前本机有 N 个账户未同步。登录后可将它们同步到账号，跨设备可见。」
→ 选项：① 同步到账号 ② 仅登录不迁移
（迁移逻辑本阶段不做，仅提示；后续单独做「显式迁移」流程）
```

### 5. 登录入口（改 P1-2）

- 保留设置页入口
- 可选项：首页/持仓页顶部或空状态处增加「登录同步」入口（P2 优化）
