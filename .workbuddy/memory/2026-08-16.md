## 网页端 ↔ 小程序 功能对齐（差异分析）

- 用户诉求：网页端已改过/修过的功能，小程序又改一遍，希望"自动匹配差异、补全没实现的功能"。
- 产物：`C:\Users\Administrator\Desktop\小程序\.workbuddy\WEB_MP_PARITY.md`（两端功能对齐清单，可反复更新）。

### 关键结论
1. 两端共用同一后端（`server/` 原生 Node http 路由分发，非 Express；`handleFundApi` 统一处理 `/api/*`）。
2. 后端 API 真源已完整提取（见清单文件 §二）。
3. **大部分功能已对齐**：总览/持仓/账户tab/数据源切换/数据标识/基金详情/AI分析/第三方同步/导出导入。
4. **架构性差异（不应盲目对齐）**：
   - 网页端 = 邮箱+密码 + Bearer token（`/api/auth/*`）+ 服务端持仓（`/api/portfolio/*`）
   - 小程序 = 微信登录 openid + 本地 storage + 微信云数据库同步（accounts 集合）
5. **可补的功能缺失（B 类）**：
   - B1 基金估值校准 `/api/fund/:code/calibration`（小程序未接入）
   - B2 股票行情 `/api/stock/:code`（小程序未接入）
   - B3 恢复默认状态（网页端有，小程序只有"恢复本地"）
6. **不适用（D 类）**：外部 Token 管理 `/api/external/token/*`（小程序 callContainer 直连用不到）。
7. 关键确认：`/api/fund/:code` 详情接口内部有 `[auto-import]` 逻辑，小程序添加基金已隐式覆盖"基金导入"，无需单独接 `/api/fund/import/:code`。

### 方法论
- 差异"匹配"可自动化（扫后端路由 + 两端调用清单）；"补全"不可纯自动（DOM↔WXML 需逐项翻译）；"补全决策"需人工判 A/B/C/D 分类。

- 深层根因：fundDetail 组件嵌在 `drawer-panel`（有 `transform: translateX(...)` 做滑入动画）里；CSS 规范中 **transform 祖先会让后代 `position: fixed` 元素相对该祖先定位，而非视口**，导致 fundDetail 内「修改持仓」`.modal-overlay`（fixed）宽度被 drawer-panel 限制，左右漏出 backdrop 灰边
- 修法（3 处联动）：
  - `portfolio.js`：data 加 `drawerSettled`；`openDetailDrawer` 滑入 300ms 后置 `drawerSettled: true`；`closeDrawer` 重置 false
  - `portfolio.wxml`：drawer-panel 加 `{{drawerSettled ? 'settled' : ''}}`
  - `portfolio.wxss`：`.drawer-panel.settled { transform: none; }`（动画完成后移除 transform，让 fixed 弹窗恢复正常铺满）
- 验证：portfolio.js 语法 OK，wxml view 50/50

### 最终根因：原生 scroll-view 裁剪 fixed 弹窗
- 上一步（settled 移除 transform）后白边仍在 → 真正根因是**微信原生 `<scroll-view>` 会裁剪内部 `position: fixed` 元素**（原生组件特性，与 transform 无关）
- 彻底修法：把 drawer 的滚动容器从原生 `scroll-view` 换成普通 `view` + `overflow-y: auto`
  - `portfolio.wxml`：`<scroll-view scroll-y class="drawer-scroll">` → `<view class="drawer-scroll">`
  - `portfolio.wxss`：`.drawer-scroll` 加 `overflow-y: auto; -webkit-overflow-scrolling: touch; min-height: 0`（普通 view 滚动，不裁剪 fixed，滚动条可被全局 CSS 隐藏）
- 验证：wxml view 51/51，scroll-view 2/2（仅剩账户 tab 横滑 + 主内容 page-scroll）
